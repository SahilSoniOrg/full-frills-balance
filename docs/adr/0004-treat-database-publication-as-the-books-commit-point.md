# Treat database publication as the books commit point

Workplace creation and restore commit the Workplace and its required books rows in one database transaction. Active workplace, Device registration, User preferences, and the Setup draft live outside that database transaction, so they are idempotent follow-up effects rather than participants in a fake cross-store transaction. A stable operation ID lets a finisher detect an already-published Workplace and retry only the remaining writes. The Setup draft is cleared last; a failure after publication retains enough intent to resume without reporting valid books as failed or relying on a second pending-workplace flag.
