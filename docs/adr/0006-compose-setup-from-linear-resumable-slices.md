# Compose setup from linear, resumable slices

Setup is a linear recipe of typed slices resolved by one small Setup Coordinator. Slices declare whether they are required, shown only when authoritative facts are missing, or always shown; they own validation and accepted output but not routing or unrelated effects. A single Device-scoped Setup draft stores the recipe, accepted checkpoints, limited fact provenance, and stable operation identity. The same draft also owns any unfinished conversational creation session, including durable unaccepted editor input and deferred-step metadata; that input is session state, not an accepted checkpoint and not a second store. Conversational creation presents seven steps (Welcome, Currency, Accounts, Income, Payments, Monthly limits, Result); Welcome is uncounted and is omitted on registered devices, leaving six counted progress steps. Welcome is the only step that may register Device identity, and only for first-run intent. Fresh setup publishes books only from its explicit finisher after Setup summary; Restore setup privately publishes validated books earlier and activates them only at acceptance. This makes Device, Workplace, Appearance, restore, and future Demo-journal slices composable without introducing a runtime plugin system, graph engine, generic form schema, or universal workflow framework.
