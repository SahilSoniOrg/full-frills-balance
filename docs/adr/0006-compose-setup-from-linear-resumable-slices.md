# Compose setup from linear, resumable slices

Setup is a linear recipe of typed slices resolved by one small Setup Coordinator. Slices declare whether they are required, shown only when authoritative facts are missing, or always shown; they own validation and accepted output but not routing or unrelated effects. A single Device-scoped Setup draft stores the recipe, accepted checkpoints, limited fact provenance, and stable operation identity. Fresh setup publishes books only from its explicit finisher after Setup summary; Restore setup privately publishes validated books earlier and activates them only at acceptance. This makes Device, Workplace, Appearance, restore, and future Demo-journal slices composable without introducing a runtime plugin system, graph engine, generic form schema, or universal workflow framework.

`services/setup` owns the shared draft types, parsing/storage, launch projection, pending creation ID, prepared-restore cache and recovery completion. Feature-owned journey recipes, screens and coordination use that shared contract. Settings recovery can finish an unchanged, satisfied empty-device creation gate without importing the Setup feature. Existing feature APIs forward to the same service instances; persisted storage keys and draft schema remain unchanged.
