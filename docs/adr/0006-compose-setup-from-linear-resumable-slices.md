# Compose setup from linear, resumable slices

Setup is a linear recipe of typed slices resolved by one small Setup Coordinator. Slices declare whether they are required, shown only when authoritative facts are missing, or always shown; they own validation and accepted output but not routing or unrelated effects. A single Device-scoped Setup draft stores the recipe, accepted checkpoints, limited fact provenance, and stable operation identity. Its conversational creation variant owns durable unaccepted editor input and deferred-step metadata; this is session state, not an accepted checkpoint or a second store. Creation presents Welcome, Currency, Accounts, Income, Payments, Monthly limits, and Result. Welcome captures the first-run name without registering the Device; it is uncounted and omitted on registered devices, leaving six counted progress steps. Creation publishes the included books atomically after explicit Result confirmation, then registers and names the Device only for first-run intent as an idempotent follow-up. Restore retains its own typed slices, privately publishes validated books earlier, and activates them only at acceptance. These are two presentations within one Setup ownership boundary, without a plugin system, graph engine, generic form schema, or universal workflow framework.
