# Sharing ownership

`SharingProvider` exposes the process-wide `sharingRuntime` above the update and Workplace gates. `useSharing` obtains stable commands; `useSharingStatus` subscribes to operation metadata. `useShareable` binds a feature's content description to share/save actions and screen disposal. Error fallback diagnostics use the same runtime through `sharingService.execute`, without React.

Content adapters declare formats and explicit device, single-Workplace, or multi-Workplace scope. They prepare data lazily after the runtime accepts an action. They do not open native presentation. Filtered transaction CSV and selected journal summaries retain their distinct schemas and amount semantics.

The runtime accepts one operation, refuses competing requests before preparation, and returns saved, handed-off, cancelled, empty, busy, or failed. A native sheet/browser download is a handoff, not proof a recipient received a file. Save/retry/optional follow-up sharing stays inside the same operation. A completed save remains saved if optional sharing fails. Preparation, destination selection, awaiting confirmation, and delivery are distinct phases. Settings shows its native progress modal only during preparation, so it cannot obscure an awaited confirmation. Busy state remains true throughout the operation.

The platform transport owns destination selection, delivery, and deferred file retention. Artifacts distinguish text, bytes, browser blobs, existing base64 ZIP output, prepared native files, and a reserved streaming destination. Audit and CSV exports share an incremental text writer. Native exports write to cache files; browsers stream to a reserved save-file destination when supported and otherwise download a blob of serialized chunks. Browser picker reservation starts synchronously from the action before asynchronous data reads.

CSV reads use 500-journal keyset pages ordered by journal date, creation time, and ID. List observation and export share the repository's filter builder. Export pages use plain records rather than populating the model cache, enrich one page, and write its rows before reading the next. The enrichment fallback also reads plain transaction/account records in batches. A creation-time cutoff excludes journals whose stored creation time is after export starts; this is a paged read, not a database-wide transactional snapshot. The browser fallback buffers output bytes, but never collects the full enriched history or joins it into one large string.

The app composition layer supplies ready/lock/restart/activity facts. Authentication and the lock overlay mount above the update gate so mandatory-update backups can authenticate. Workplace bootstrap still mounts independently of the financial-content guard, avoiding a splash/hydration deadlock. Workplace transition entry points cancel affected preparation before asynchronous switching/deletion. A screen aborts its preparation when unmounted. Lock, scope invalidation, and screen disposal remain recorded during destination selection even if conditions recover before the picker returns; any reserved writer is aborted before reading data. A final native handoff retains its completed outcome and is never automatically replayed. Native inactivity is distinct from loss of authentication, so returning from the application's own picker does not bypass app lock or automatically repeat export.

React snapshots contain operation identity, phase, and progress only. All consumers subscribe to the busy boolean; only the operation owner subscribes to changing phase and progress. Financial rows and file bytes remain inside the operation. Screen privacy masking remains independent from export contents. `useJournalCsvExport` owns CSV-specific controls and copy, leaving `useShareable` format-independent.

All delivery callers use scoped content adapters and `execute` or `useShareable`. Selected-journal formatting is independent of delivery; there is no legacy provider conversion or exception-based delivery API. No second runtime is constructed by the provider. Tests can inject a runtime/transport without opening native UI.

Provider composition remains separate: sharing survives Workplace unmounting and serves diagnostics, while privacy scope is screen-local and shell readiness/lock/restart have their own subscriptions. Grouping mounting in the future need not merge these state owners or change their public hooks.
